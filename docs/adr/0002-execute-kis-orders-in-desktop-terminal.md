# 0002. KIS 주문을 데스크톱 터미널에서 실행하고 자격증명은 OS 키체인에 보관합니다

- 날짜: 2026-03-31
- 상태: 채택
- 결정한 사람: @keonha123
- 대체한 ADR: 없음
- 대체된 ADR: 없음

## 배경

처음에는 backend 가 한국투자증권(KIS) API 를 직접 호출했습니다. 2026-03-26 커밋 `f044936` 이 backend 에
`KisApiClient` 와 `KisTokenManager` 를 넣었습니다. KIS 앱 키·시크릿·계좌번호는 서버 환경변수(`broker.kis.*`)로
주입하는 단일 모의투자 계정 구조였고, 사용자별 키를 다루는 경로는 아직 없었습니다.

PR #8 본문은 이 구조를 바꾸는 이유로 자본시장법(미등록 투자일임업 방지)과 Zero Trust 보안 원칙을 들었습니다.
같은 날 작성된 `trading-terminal/README.md`(커밋 `0b6b304`)는 여기에 KIS API 약관(키 중앙 집중화 금지)을 더해, 실제 주문은
사용자 PC 에서 실행하고 KIS API 키는 중앙 서버로 보내지 않는다고 적었습니다.

## 결정

KIS 호출은 트레이딩 터미널의 Electron main process 만 합니다. backend 는 KIS 를 호출하지 않습니다.

- PR #8(커밋 `b31ac6e`)에서 backend 의 `infrastructure/broker` 패키지와 `broker.kis.*` 설정을 지웠습니다.
  backend 는 거래를 PENDING 으로 기록하도록 바뀌었습니다. 터미널이 주문 결과를 보고하는
  `POST /api/v1/trades/{tradeId}/callback` 은 커밋 `a2a1738`(2026-04-03)에서 구현했습니다.
- 터미널의 `KisService` 가 KIS REST 를 호출합니다. 앱 키, 시크릿, 계좌번호, 발급받은 접근 토큰은 `keytar` 로
  OS 키체인에 저장합니다(서비스 이름 `EarningWhisperer`). 모의투자와 실전 키는 별도 슬롯에 둡니다
  (`kis-appKey-paper` / `kis-appKey-real` 등, #70).
- 주문 수량도 터미널이 계산합니다. 커밋 `d7af41a`(2026-04-12)부터 backend 는 비율(`order_ratio`)까지만 정하고,
  터미널이 실제 잔고와 현재가로 최종 수량을 산출합니다. 커밋 메시지는 이유로 "중앙 서버의 수량 결정을 배제해
  미등록 투자일임업 리스크를 회피" 를 적었습니다.

## 검토한 대안

### backend 가 KIS 를 직접 호출

실제로 구현했다가 5일 뒤 걷어낸 방식입니다(`f044936` → `b31ac6e`). 고르지 않은 이유는 배경에 적은 법·약관·보안
원칙입니다. 이 외의 비교(성능, 운영 비용 등) 기록은 없습니다.

### keytar 대신 electron-store

같은 `trading-terminal/README.md` 초안은 보안 저장소 후보로 "`keytar` 또는 `electron-store`" 를
함께 적었습니다. `keytar` 를 고른 이유는 기록이 없습니다.

## 결과

좋아진 점

- 사용자의 KIS 키와 계좌번호가 서버와 DB 에 남지 않습니다.
- 주문 실행과 수량 결정이 사용자 PC 에서 일어나므로, 서버가 사용자 대신 매매를 결정하는 구조를 피합니다.

감수한 비용

- 주문 기능은 데스크톱 앱에서만 쓸 수 있습니다.
- `keytar` 는 네이티브 모듈이라 설치 후 `electron-rebuild -f -w keytar`(`postinstall`)로 다시 빌드해야 하고
  빌드 도구가 필요합니다.
- backend 의 거래 기록은 터미널의 보고에 의존합니다. 터미널이 보고하지 못하면 거래가 PENDING 으로 남으므로
  TTL 만료 처리가 따로 필요해졌습니다(#64).
- KIS 호출 제한, 토큰 수명, 거래소 코드 해석 같은 KIS 연동 문제를 모두 터미널 쪽에서 처리합니다
  (예: 커밋 `42a0ec3` 통합 rate limiter, `e99598e` 티커별 거래소 코드).

후속 조치

- 에러 로그에 KIS 자격증명이 평문으로 찍히는 경로를 막았습니다(커밋 `88b8ba8`).
- 키를 수정하면 옛 키로 발급한 접근 토큰이 무효가 되므로, `KisService.saveCredentials` 는 키를 저장할 때
  해당 모드의 토큰 슬롯을 함께 비웁니다.
- 2026-10-05 PR #142(#127)에서 서버가 주문을 지시하던 경로를 모두 걷어내 현재는 사용자가 직접 낸 주문만
  터미널이 실행합니다. 이에 따라 `order_ratio` 도 제거되어, 결정 절의 비율 결정 서술은 더 이상
  해당하지 않고 주문 수량은 사용자가 Trading Room 에서 직접 입력합니다. KIS 호출을 터미널에서만 하고 키를 OS
  키체인에 두는 결정은 그대로입니다. 매매를 직접 주문만으로 한정한 결정은
  [0005](0005-support-only-user-placed-orders.md)에 있습니다.
