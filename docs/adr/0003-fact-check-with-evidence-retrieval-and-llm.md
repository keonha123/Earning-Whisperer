# 0003. 어닝콜 팩트체크를 ai-engine 의 근거 검색과 LLM 2패스 판정으로 처리합니다

- 날짜: 2026-09-09
- 상태: 채택
- 결정한 사람: @keonha123
- 대체한 ADR: 없음
- 대체된 ADR: 없음

## 배경

2026-09-09 이전의 트레이딩 터미널 팩트체크 패널은 목업이었습니다. 개발 빌드에서 렌더러가 고정 데이터를
타이머로 뿌렸고 판정 4종(`CONFIRMED` / `EXAGGERATED` / `SHIFTED` / `UNVERIFIED`)도 화면에서 정한 값이었습니다
(커밋 `b2d5e13`, `7163fad`).

ai-engine 에는 팩트체크 경로가 두 개 있었습니다. `POST /v1/engine/fact-check` 는 HTTP 로 열려 있었지만 LLM
없이 단어 겹침으로 판정했습니다. 2026-07-12 커밋 `5bb316a` 에서 들어온 `LiveNewsFactCheckService`(작성 @yytss3)는
구현만 있고 어떤 라우터에도 연결되지 않아 호출할 수 없었습니다(커밋 `a44f8c8` 메시지).

## 결정

어닝콜 팩트체크는 `LiveNewsFactCheckService` 를 씁니다. 커밋 `a44f8c8` 에서
`POST /v1/engine/live-fact-check/sentence` 라우터를 붙였고, 커밋 `2ecbf46` 에서 backend 의 `AiEngineClient` 가
이 경로를 호출하도록 연결했습니다.

- backend 는 확정된 문장을 한 개씩 순서대로 제출합니다.
- ai-engine 은 ticker 별로 문장을 모으다가 3문장이 차면 한 배치를 처리합니다. 처리 순서는 LLM 으로 검증 가능한
  주장 추출 → 주장별 근거 문서 검색 → LLM 으로 주장과 근거 대조입니다.
- 판정은 `SUPPORTED` / `CONTRADICTED` / `INSUFFICIENT_EVIDENCE` 3종이고 결과는 backend 가
  `/topic/factcheck/{ticker}` 로 발행합니다. 요청·응답 형식은 [API 명세](../api-spec.md)의 Contract 9 와 4.6 에
  있습니다.
- 터미널 화면은 판정을 각각 "사실 확인 / 사실과 다름 / 근거 부족" 으로 표기합니다(커밋 `b57d27c`).

## 검토한 대안

### 기존 단어 겹침 경로(`/v1/engine/fact-check`)

커밋 `a44f8c8` 에서 같은 입력을 두 경로에 넣어 비교했습니다. "OCI 42% 성장" 근거에 "52% 성장" 주장을 넣었을
때 기존 경로는 `SUPPORTED`(0.90)로 통과시켰고 새 경로는 `CONTRADICTED`(0.85)와 근거 인용을 돌려줬습니다.
숫자가 다른 주장을 걸러 내지 못해 고르지 않았습니다.

### 목업의 판정 4종 유지

`EXAGGERATED`(과장)와 `SHIFTED`(논점 이동)는 ai-engine 에 없는 판정입니다. 엔진의 3종을 기준으로 삼고 과장
사례는 `CONTRADICTED` 와 `explanation_ko` 의 설명으로 전달하기로 했습니다(커밋 `b57d27c`).

### 배치 크기

3문장 단위를 고른 이유와 다른 크기를 검토한 기록은 없습니다.

## 결과

좋아진 점

- 화면의 판정이 엔진이 실제로 검증한 결과가 되었습니다. 월마트 콜 24문장에서 나온 주장 29건의 실측 결과는
  [시연 자료](../demo/README.md)의 "팩트체크 정확도" 절에 있습니다. 근거 본문 절단을 고친 뒤
  `SUPPORTED` 7 / `CONTRADICTED` 0 / `INSUFFICIENT_EVIDENCE` 22 였습니다.

감수한 비용

- 한 배치에 LLM 호출이 두 번 들어가 판정까지 5~15초가 걸립니다. 터미널은 발언은 나왔지만 판정이 아직 없는 구간을
  "분석 중" 으로 표시합니다(커밋 `b57d27c`).
- 세션 끝에 3문장이 차지 않은 나머지 문장은 판정하지 않고 버립니다(`DISCARDED`). 시연 스크립트를 24문장(3의
  배수)으로 맞춘 이유입니다(커밋 `2c64563`).
- ai-engine 이 순서가 거꾸로 온 문장을 `REJECTED` 로 버리므로, backend 는 팩트체크 제출을 단일 스레드로
  직렬화합니다(커밋 `2ecbf46`).
- 판정 품질이 적재된 근거 문서에 달려 있습니다. 근거를 적재하지 않으면 모든 판정이 근거 부족으로 나오고
  이 화면은 정상 결과와 구별되지 않습니다. backend 는 재생 시작 응답에 `evidence_warning` 을 싣습니다
  (커밋 `af2b987`).

후속 조치

- 프롬프트에 싣는 근거 본문이 600자로 잘려 `CONTRADICTED` 4건이 모두 오판이었습니다. 4,000자로 늘리고
  프롬프트에 모순 판정 조건(지표·주체·회계기간 일치)을 명시해 고쳤습니다(커밋 `7d962d0`).
- 남은 한계는 [시연 자료](../demo/README.md)에 정리되어 있습니다. 가이던스 주장 2건이 근거 없이 `SUPPORTED` 로
  통과한 점, 가장 강한 근거가 콜 당일 실적 보도라 검증이 부분적으로 순환하는 점, 관련도 임계 때문에 주장당
  근거가 대개 1건인 점입니다.
- `AiEngineClient` 는 팩트체크 실패를 모두 흡수하고 재생은 계속합니다. `AI_ENGINE_FACT_CHECK_ENABLED=false` 이면
  ai-engine 없이 재생만 합니다.
