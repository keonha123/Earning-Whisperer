# 0006. 어닝콜 질의응답은 별도 서비스 logothea-assistant 가 답합니다

- 날짜: 2026-10-06
- 상태: 채택
- 결정한 사람: @keonha123
- 대체한 ADR: 없음
- 대체된 ADR: 없음

## 배경

어닝콜을 보는 사용자가 콜 내용을 묻고 근거와 함께 답을 받는 기능(#112)을 더하기로 했습니다. 기존 분석
기능(팩트체크, 직전 콜 대조, 번역, 종합 판단)은 콜마다 한 번 계산해 모든 사용자에게 같은 결과를 나눠 줍니다.
질의응답은 사용자가 질문할 때마다 LLM 을 부르므로 부하가 사용자 수와 질문 수에 따라 늘어납니다.

ai-engine 은 uvicorn 워커 하나로 돌고, 무료 등급 Gemini 키를 기존 기능이 함께 써서 모델별 분당 15요청 한도에
가깝습니다. 답변 생성 위치, 근거를 찾는 곳, 쓸 LLM 을 정해야 했습니다.

## 결정

질의응답은 새 최상위 모듈 `logothea-assistant`(Python, FastAPI)가 답합니다. 별도 프로세스와 systemd 서비스로
돌고 루프백(`127.0.0.1:8100`)에만 바인딩합니다.

- backend 가 유일한 외부 진입점입니다. JWT 인증, 사용자별 하루 한도, 질문 시점 확정, 답변 스트림 중계를
  맡습니다. 근거로 쓸 세그먼트를 콜 단위로 Redis 에 저장하고 내부 API 로 내줍니다.
- 뉴스와 직전 콜 문장 검색은 ai-engine 이 계속 맡습니다. 질의 임베딩이 적재 때와 같은 모델이어야 하므로 검색은
  ai-engine 한 곳에 둡니다. 질의응답용으로 시점 조건 검색 엔드포인트를 새로 더했습니다.
- 답변은 OpenAI 를 단일 공급자로 씁니다. 공식 SDK 위에 얇은 자체 인터페이스를 두고 어댑터는 OpenAI 하나만
  둡니다. 공급자 장애 시에는 다른 공급자로 넘기지 않고 오류를 보여 줍니다.
- 처리는 고정 RAG 파이프라인(분류 → 정해진 근거 수집 → 인용을 포함한 생성 → 인용 검증)으로 시작해 평가
  하네스로 기준 점수를 잽니다. 그 뒤 도구 호출 에이전트 방식을 더해 같은 질문셋으로 비교합니다.

#112 설계에서 2026-10-06 에 정했고, PR #170(근거 데이터 계층), #173(서비스), #178(backend 엔드포인트)로
반영했습니다.

## 검토한 대안

### ai-engine 안에서 답한다

모듈이 늘지 않습니다. 다만 질문이 몰리면 같은 프로세스의 실시간 팩트체크와 번역이 늦어집니다. 사용자 질문마다
부르는 기능과 콜마다 한 번 도는 기능은 부하 형태와 배포 주기가 달라 고르지 않았습니다.

### backend 안에서 답한다

backend 가 이미 인증과 한도를 맡고 있어 경로가 짧아집니다. 다만 Spring AI 를 쓰려면 지금의 Spring Boot 3.3 을 Spring AI 가 지원하는
버전으로 먼저 올려야 해서 고르지 않았습니다.

### 서버의 공유 Gemini 무료 키로 답한다

추가 비용이 없습니다. 다만 분당 15요청 한도를 기존 기능과 나눠 써야 해서 기존 기능을 유지하면서 여러 사용자의
질문을 받을 수 없어 고르지 않았습니다.

### 여러 공급자를 묶는 라이브러리(LiteLLM)를 쓴다

공급자를 바꾸기 쉬워집니다. 다만 공급자를 하나만 쓰기로 해서 얻는 것이 적습니다. 당시 열린 버그가 있었고
2026-03 에 PyPI 패키지 탈취 사고가 있었던 점도 고려해 고르지 않았습니다.

## 결과

좋아진 점

- 질의응답 부하와 장애가 실시간 분석 경로와 나뉩니다. assistant 가 꺼져 있어도 자막, 팩트체크, 번역, 종합 판단은
  그대로 돕니다.
- 외부에서 닿는 곳은 backend 하나라 인증과 한도를 한 곳에서 관리합니다.

감수한 비용

- 배포하고 감시할 서비스가 하나 늘었습니다. 질문에 따라 OpenAI 비용이 생기며, 사용자당 하루 50회 한도로
  묶습니다.
- 공급자가 하나라 OpenAI 장애 중에는 질의응답을 쓸 수 없습니다.

후속 조치

- 시연 서버의 assistant systemd 유닛과 배포 스크립트 지원은 아직 저장소에 없습니다(#198).
- 고정 방식과 에이전트 방식의 비교 평가가 남아 있습니다(#194). 에이전트 방식은 `ANSWER_MODE=agent` 로 켜며
  기본값은 고정 방식입니다.
