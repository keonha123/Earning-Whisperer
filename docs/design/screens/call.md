# 콜 화면

어닝콜 하나를 시작 전부터 끝난 뒤까지 따라가는 화면입니다. Logothea 의 중심 화면이며, 같은 화면이 콜의 시간에
따라 주인공을 바꿉니다. 흐름과 이유는 [UX 문서](../ux.md)의 콜 준비 · 콜 시청 · 콜 종료 후 판단 · 주문 흐름에,
재질과 색은 [디자인 시스템](../design-system.md)에 있습니다.

코드는 `trading-terminal/src/renderer/pages/TradingRoomPage.tsx`(경로 `/call?ticker=`)와
`components/call/` 에 있습니다.

## 들어오는 길

- 종목 브리핑의 `콜 화면 열기`
- 메뉴 맨 위의 열린 콜 자리
- 홈의 진행 중인 콜, `시연 재생`(시연 종목으로 열고 재생을 바로 시작합니다)

콜 화면을 열면 메뉴 맨 위에 열린 콜 자리가 생기고, 그 자리의 닫기로 세션을 끝냅니다.

## 콜 상태

| 상태 | 판단 기준 | 주인공 | 보조 |
|---|---|---|---|
| 시작 전 | 받은 자막이 없습니다 | 브리핑 | 가격과 내 포지션 |
| 진행 중 | 마지막 자막의 콜이 종료 표시를 받지 않았습니다 | 자막 | 대조 · 질문 · 가격 탭 |
| 종료 후 | 마지막 자막의 콜이 종료 표시를 받았거나, 종합 판단이 도착했습니다 | 종합 판단 | 자막 다시 보기 |

같은 종목을 다시 재생하면 지난 회차 자막이 남아 있을 수 있어, 화면에는 가장 최근 콜의 자막만 보입니다. 판단
기준은 `lib/callScreen.ts` 에 있고 단위 테스트가 있습니다.

## 영역

### 콜 바

화면 위쪽에 떠 있는 맑은 유리 캡슐입니다. 내용이 이 아래로 지나가므로 굴절을 걸고, 각 면의 위쪽은 서서히
어둡게 덮어 바의 글자와 겹쳐 읽히지 않게 합니다.

| 위치 | 내용 |
|---|---|
| 왼쪽 | 종목, 회사명, 콜 상태(시작 전 · LIVE · 종료), 시연 표시 |
| 가운데 | 경과 시간(마지막 자막 기준), 비교 대상 직전 콜 |
| 오른쪽 | 시연 제어, 발화자, 종목 정보, `주문` |

- `주문` 이 이 화면의 유일한 색상 유리 주 버튼(라피스)입니다.
- LIVE 는 무채색 점멸로 나타냅니다. 빨강은 가격 상승에만 씁니다.
- 비교 대상은 첫 대조 항목이 도착해야 알 수 있어, 그 전에는 "첫 대조가 오면 표시합니다" 로 둡니다.
- 시연은 홈의 `시연 재생` 으로만 시작합니다(`/call?ticker=WMT&demo=start`). 콜 바의 시연 제어는 시연 중일
  때만 보이며 `중지` · `처음부터`(진행 중), `처음부터`(종료 후)입니다. 실제 콜에는 시연 제어가 없습니다.
  `처음부터` 는 재생을 멈추고 지난 회차 자막을 비우고 다시 시작합니다. 지난 회차 자막은 새 재생이 실제로 시작된
  뒤에 비웁니다. `중지` 하면 서버가 종료 표시를 보내지 않으므로 이 화면에서 그 콜을 끝난 것으로 다루고, 판단
  자리에 "시연을 중지했습니다" 를 씁니다.

### 시작 전 — 브리핑

"이 콜을 듣기 전에 알아야 할 것" 을 위에서부터 둡니다.

1. 콜 시작까지 남은 시간과 일정(KST, 괄호 안에 미 동부 시각, 확정 · 예정)
2. 시장 기대치(EPS · 매출 컨센서스)
3. 최근 어닝 반응(분기별 EPS 예상 → 실제, 발표일 주가 반응)
4. AI 사전 요약 — 자리만 둡니다

일정이 없으면 "예정된 실적 발표가 없습니다", 예정 시각이 지났는데 자막이 없으면 "예정 시각이 지났습니다 · 첫
자막을 기다립니다" 로 씁니다. 옆 자리는 가격과 내 포지션입니다.

### 진행 중 — 자막

- 서리 유리 위에 시각 · 발화자 · 본문 순으로 쌓습니다. 발화자를 누르면 발화자 프로필이 열립니다.
- 직전 콜 대조는 해당 발언 바로 아래에 붙습니다. `후퇴` 이거나 위험 점수가 0.7 이상이면 카드로 펼치고 직전
  발언과 이번 발언 원문을 나란히 둡니다. 나머지는 기호가 붙은 칩이고 누르면 같은 카드로 펼쳐집니다.
- 맨 아래를 보고 있을 때만 따라 내려갑니다. 위로 올려 읽는 동안에는 움직이지 않고 "새 발언 N개" 버튼으로
  알립니다. 대조 카드가 늦게 붙어 높이가 늘어도 맨 아래를 보고 있었다면 따라 내려갑니다.
- 위쪽의 `원문 / 원문 + 번역` 전환으로 번역을 켜고 끕니다. 번역을 켠 채로 시작합니다. 번역은 원문 몇 문장을
  묶어 몇 초 늦게 오므로, 묶음의 마지막 발언 아래에 왼쪽 선을 그은 `번역` 문단으로 붙습니다. 번역에 실패한
  묶음은 오지 않고, 지난 회차 번역은 보이지 않습니다.
- 번역문 안의 전문용어(기존점 매출, 가이던스 등)는 점선 밑줄입니다. 초보 투자자가 어려운 용어를 이해하도록,
  누르면 용어 옆에 짙은 서리 유리 팝오버로 번역어 · 원문 용어와 쉬운 설명 한 단락(뜻, 이어서 수치를 읽는 법)을
  보여 줍니다. 설명을 칸으로 나누거나 제목을 붙이지 않습니다. 사전은 미리 받아 두어 누를 때 기다리지 않습니다. Esc,
  바깥 클릭, 스크롤로 닫힙니다. 사전을 받지 못하면 "용어 설명을 불러오지 못해 번역만 보여 줍니다" 를 쓰고
  밑줄 없이 번역만 둡니다.
- 종료 후 좁은 다시 보기에도 같은 설정으로 번역이 붙습니다.

옆 자리는 세 탭입니다.

| 탭 | 내용 |
|---|---|
| 대조 | 변화 유형별 개수, 발언 순서대로 정렬한 대조 목록. 항목을 누르면 자막이 그 발언으로 옮겨 가고 잠시 강조됩니다 |
| 질문 | 지금까지 나온 콜이나 고른 발언에 대해 묻는 질의응답(#112). 아래 "질문" 절 |
| 가격 | 가격과 내 포지션 |

### 질문

콜 내용에 대해 묻고 근거와 함께 답을 받는 자리입니다. 진행 중에는 옆 자리의 `질문` 탭, 종료 후에는 오른쪽
판 위의 `판단 / 질문` 전환으로 엽니다. 대화는 콜 회차에 묶여 탭을 오가도 이어집니다.

- 범위: 맨 위에 늘 보입니다. 기본은 콜 전체이고, 자막 발언 줄에 마우스를 올리면 나타나는 `이 대목 질문` 을
  누르면 그 발언이 범위가 되어 옅은 면의 인용으로 보입니다. `콜 전체로` 로 되돌립니다. 범위가 바뀌면 새 대화입니다.
- 추천 질문 5개: 대화가 비어 있을 때 맑은 유리 버튼으로 둡니다. 추천 질문은 고른 대목과 관계없이 콜 전체로
  답한다는 점을 함께 씁니다.
- 질문은 오른쪽 옅은 면의 말풍선, 답은 왼쪽 본문입니다. 말풍선과 인용은 읽는 내용이라 유리를 쓰지 않습니다. 답은 스트리밍으로 늘어나며 끝에 커서를 둡니다. 아직
  아무것도 오지 않았으면 "콜 내용에서 근거를 찾고 있습니다…" 를 씁니다.
- 근거 표시(`[S12]` 등)는 본문 속 작은 번호 칩이 되고, 답 아래 `근거` 목록의 같은 번호와 짝입니다. 칩을 누르면
  그 근거가 잠시 밝아집니다. 이번 콜 발언 근거에는 `자막에서 보기` 가 있어 자막이 그 발언으로 옮겨 갑니다.
  원문과 일치하는지 확인하지 못한 근거와 목록에 없는 표시는 점선 테두리 · 흐린 글자에 "원문과 일치하지 않을 수
  있습니다" 를 붙입니다. 답은 지우지 않습니다.
- 끝 상태: 거절이면 거절 문구 아래에 대신 볼 추천 질문을 둡니다. 오류면 danger 색 문구와 `다시 질문`, 하루
  한도면 다시 질문할 수 있는 한국 시간을 쓰고 입력칸을 막습니다. 취소한 턴은 "질문을 취소했습니다" 입니다.
- 불러오지 못한 자료(뉴스 · 지난 분기 콜 등)가 있으면 답 아래에 한 줄로 알립니다.
- 진행 중인 콜이면 "콜 mm:ss 시점까지의 내용으로 답했습니다" 를 답 끝에 둡니다.
- 입력칸 바로 위에 상시 고지를 늘 둡니다. 입력칸 아래에 남은 질문 수와 글자 수(500자)를 쓰고, 답이 오는 동안은
  `질문하기` 가 `답변 멈추기` 로 바뀝니다. Enter 로 보내고 Shift+Enter 로 줄을 바꿉니다. 대화당 4개를 다 쓰면
  마지막 답이 끝난 뒤 입력칸 대신 `새 대화` 를 둡니다. 화면 낭독기에는 늘어나는 답 대신 "답변을 받는 중" ·
  "답변이 끝났습니다" 같은 짧은 상태만 알립니다.
- 색상 유리 주 버튼은 콜 바의 `주문` 하나라서 이 자리의 버튼은 모두 맑은 유리입니다.

### 종료 후 — 종합 판단

| 순서 | 내용 |
|---|---|
| 1 | 실행 판단: 권고 행동과 실행 조건(통과 올리브 · 조건부 보류 `ink-2` · 차단 포르피라), 포지션 의도, 보류 사유 |
| 2 | 방향(색 없이 글자로), 촉매, 강도 · 신뢰도 막대, 기관 등급 |
| 3 | 펼쳐 보기: 판단 근거(영어 원문), 반대 논거 · 리스크, 질문 회피, 파급 영향, 손절 · 익절 계획(참고용) |
| 4 | 부가 정보 누락 안내, 엔진 경고, 모델과 생성 시각 |
| 5 | 직전 콜 대조 집계 |

- 파급 영향의 종목을 누르면 그 종목 브리핑이 열립니다.
- 손절 · 익절 계획은 주문 입력과 연결하지 않습니다.
- 판단의 callId 가 지금 콜과 다르면 지난 회차 판단이라 보이지 않고 콜 상태를 정하는 데도 쓰지 않습니다.
- 판단이 오기 전에는 "콜 전체를 종합하는 중입니다", 3분이 지나도 오지 않으면 받지 못했다는 안내로 바꿉니다.
  판단 재요청은 서버 작업이 필요해 아직 없습니다.
- 자막은 왼쪽 좁은 자리에서 다시 봅니다. 대조는 칩으로만 보입니다.

### 주문 시트

콜 바의 `주문` 으로 여닫는 오른쪽 시트입니다. 콜 바 아래에서 시작해 `주문` 버튼을 가리지 않습니다. 읽고
입력하는 면이라 서리 유리이고, 화면 중심 판의 금테(가장 굵은 단계)를 두릅니다.

1. 맨 위에 주문이 나가는 계좌를 크게 씁니다: KIS 모의투자 · KIS 실전투자 · 페이퍼 계정. 계좌를 모르면 "계좌
   확인 중" 으로 두고 전송을 막습니다.
2. 매수 · 매도, 수량과 최대 수량(매수는 예수금 ÷ 실제 주문 단가, 매도는 보유 수량), 즉시 체결 · 지정가.
3. 즉시 체결을 고르면 "미국 주식은 시장가 주문이 없어 현재가보다 1% 높은(매도는 낮은) 지정가로 냅니다" 와
   실제 단가를 보여 줍니다.
4. 예상 금액과 예수금.
5. `매수 확인` · `매도 확인` → 확인 단계(계좌 · 종목 · 방향 · 수량 · 가격 · 예상 금액) → `주문 보내기`.
   확인 단계는 늘 거칩니다. 실전 계좌의 `주문 보내기` 는 위험 행동(포르피라)입니다. 보내기 직전에 수량 · 가격 ·
   한도를 다시 확인합니다. 수량은 정수만 받고, 보유 수량을 모르면 매도를 막습니다.
6. 이번 세션 주문: 접수 → 체결 · 부분 체결 · 실패. 접수 주문이 있으면 `체결 확인` 으로 다시 확인합니다.

KIS 계좌인데 키가 없으면 입력 대신 설정의 키 등록으로 안내합니다. 페이퍼 계정은 키가 필요 없습니다. Esc, 닫기,
바깥 클릭으로 닫힙니다. 시트는 덮개를 깔지 않아 열린 동안에도 자막과 콜 바를 그대로 씁니다. 열면 계좌 제목으로,
확인 단계로 넘어가면 확인 제목으로 포커스가 옮겨 가고, 닫으면 `주문` 버튼으로 돌아옵니다.

## 표시 데이터

| 영역 | 출처 |
|---|---|
| 자막 | STOMP `/topic/transcript/{ticker}` (`useLiveTranscript`) |
| 직전 콜 대조 | STOMP `/topic/transcript-diff/{ticker}` (`useTranscriptDiff`) |
| 질의응답 | `ASSISTANT_ASK` · `ASSISTANT_EVENT` 스트림 (`useAssistantStore`) |
| 번역 · 용어 밑줄 | STOMP `/topic/transcript-translation/{ticker}`, 용어 사전 `GLOSSARY_GET` (`useTranscriptTranslation`) |
| 종합 판단 | STOMP `/topic/evaluation/{ticker}` (`useEarningsSummary`) |
| 브리핑 · 30일 차트 · 회사명 | `STOCK_GET_DETAIL` (`useCompanyDetail`) |
| 현재가 · 등락 | 시세 갱신 (`usePrices`), 없으면 종목 상세의 현재가 |
| 보유 · 예수금 | 잔고 store (`usePortfolioStore`) |
| 계좌 | 로그인 응답의 계좌 종류, `SETTINGS_GET_PAPER_TRADING` |
| 발화자 | 콜 참가자 명부 (`useSpeakerProfiles`) |

뉴스 대조 팩트체크는 제품 범위에서 빠져 화면에 그리지 않습니다. 수신 코드는 아직 남아 있고 제거는 별도
작업입니다.

## 아직 정하지 않은 것

- 분봉 차트(1분 · 5분 · 1시간 · 1일) — 데이터가 없어 자리만 둡니다
- 지난 콜 다시 보기와 판단 재요청 — 서버가 콜 결과를 저장하고 돌려줘야 합니다
