# 로그인 · KIS 키 등록 권유

앱을 열면 처음 나오는 화면입니다. 로그인한 뒤 이 PC 에 KIS 키가 없으면 같은 자리에서 키 등록을 권합니다.
흐름과 이유는 [UX 문서](../ux.md)의 처음 시작 흐름에, 재질과 색은 [디자인 시스템](../design-system.md)에,
로고 사용 규칙은 [브랜드 문서](../brand.md)의 로고와 앱 아이콘 절에 있습니다.

코드는 `trading-terminal/src/renderer/pages/AuthPage.tsx`(경로 `/auth`), `components/auth/`,
`components/settings/KisKeyForm.tsx` 에 있습니다.

## 들어오는 길

- 앱 실행
- 로그인 세션이 만료되었을 때 (`AUTH_EXPIRED` → `/auth`)
- 로그아웃

## 단계

| 단계 | 나오는 조건 | 다음 |
|---|---|---|
| 로그인 | 늘 처음에 나옵니다 | 키가 있으면 홈, 없으면 키 등록 권유 |
| 키 등록 권유 | 로그인 직후 `VAULT_HAS` 가 모의 · 실전 모두 없음일 때. 조회에 실패하면 이미 있는 키를 덮어쓰지 않도록 권유 없이 홈으로 갑니다. 페이퍼 계정은 KIS 키가 필요 없어 늘 홈으로 갑니다 | `저장하고 시작` · `나중에` 모두 홈 |

키 등록 권유는 건너뛸 수 있습니다. 분석 기능은 키 없이 모두 쓰고, 키 없이 주문을 열면 주문 시트가 설정의
등록 칸으로 안내합니다([설정 화면](settings.md)).

## 영역

바탕은 단색이고 장식을 두지 않습니다. 화면 가운데에 브랜드와 판 하나가 세로로 놓입니다.

### 브랜드

- 어두운 바탕용 가로 조합(심볼 + 흰 워드마크)과 한 줄 소개 "어닝콜을 들으며 판단하고 주문합니다".
- 로고 둘레 여백과 최소 크기는 브랜드 문서를 따릅니다.

### 로그인 판

입력하는 면이라 서리 유리에 떠 있는 금테(중간 굵기)를 두릅니다.

1. 제목 `로그인`
2. `이메일`, `비밀번호`(보기 · 숨기기 전환). 비밀번호 칸 오른쪽 위에 `비밀번호 찾기`
3. `자동 로그인`
4. 오류 문구 자리 — 비어 있어도 높이를 잡아 둡니다
5. `로그인` — 이 화면의 색상 유리 주 버튼(라피스)
6. `또는` 구분선, `Google로 계속하기` · `카카오로 계속하기` — 맑은 유리 버튼이고 회사 색은 로고 아이콘에만 둡니다

판 아래에 "계정이 없으면 `웹사이트에서 가입`" 과 앱 버전, 화면 왼쪽 아래에 언어(`한국어`)를 둡니다.

### 키 등록 권유 판

로그인 판과 같은 재질입니다.

1. 제목 `주문용 KIS 키 등록`과 설명: 분석은 키 없이 쓰고, 주문하려면 키가 필요하며, 나중에 설정에서 등록해도
   된다는 내용
2. 전환 `KIS 모의투자 | KIS 실전투자`(기본 모의투자)와 고른 계좌의 한 줄 안내. 실전투자는 주의색 글자로
   "실제 돈으로 주문하는 계좌입니다. 체결되면 되돌릴 수 없습니다" 를 씁니다
3. `App Key`, `App Secret`(보기 · 숨기기 전환), `계좌번호`(숫자 8자리 또는 10자리), `HTS ID (선택)`와
   HTS ID 설명
4. 오류 문구 자리
5. 왼쪽 `나중에`(맑은 유리), 오른쪽 `저장하고 시작`(올리브, 확인)

전환으로 고른 계좌가 주문할 계좌(활성 모드)가 됩니다. 다른 계좌의 키는 설정에서 더 등록합니다. 전환을 바꾸면
입력칸을 비웁니다. 다른 계좌의 키가 섞여 저장되지 않게 하기 위해서입니다.

## 동작

| 행동 | 결과 |
|---|---|
| 이메일 로그인 | `AUTH_LOGIN`. 실패하면 "이메일 또는 비밀번호가 올바르지 않습니다" 로 원인을 구분하지 않고, 연결 실패만 따로 씁니다 |
| 소셜 로그인 | `AUTH_OAUTH_START`. 기본 브라우저에서 인증하고, 진행 중에는 다른 로그인 버튼을 모두 막습니다 |
| `저장하고 시작` | 실전투자면 확인 대화상자(위험 행동 버튼) → `SETTINGS_SET_PAPER_TRADING`(고른 계좌) → `VAULT_SAVE`(HTS ID 포함) → `VAULT_HAS` 재조회 → 홈 |
| `나중에` | 아무것도 저장하지 않고 홈 |

- 신규 등록이라 `App Key` · `App Secret` · `계좌번호` 는 모두 필요합니다. 비어 있으면 저장 전에 막습니다.
- `VAULT_SAVE` 가 실패하면 바꿔 둔 모드를 원래대로 돌립니다. 키 없는 실전 모드로 남은 채 `나중에` 로 들어가지 않게 하기 위해서입니다.
- 저장에 실패하면 입력 검증 사유는 판 안에 그대로 쓰고, 그 밖의 오류는 고정 문구와 오류 알림으로 알립니다. 입력값은 남겨 다시 시도할 수 있게 합니다.
- 저장하는 동안과 실전 확인 창이 떠 있는 동안에는 계좌 전환과 다시 제출을 막습니다.
- 이동 결정과 저장 순서는 `lib/kisOnboarding.ts` 에 있고 단위 테스트가 있습니다.
- 입력한 키는 저장 뒤와 화면을 떠날 때 비웁니다. App Secret 칸은 비밀번호 자동 완성을 받지 않습니다.

## 자리만 있는 것

아래 요소는 동작하지 않습니다. 흐리게 두고, 누르면 "준비 중" 알림을 띄웁니다.

| 요소 | 이유 |
|---|---|
| `자동 로그인` | 로그인 정보를 디스크에 남기지 않아, 보관 방식을 정하기 전에는 켤 수 없습니다. 켜진 것처럼 보이지 않게 빈 상자로 둡니다 |
| `비밀번호 찾기` | 기능이 없습니다 |
| `웹사이트에서 가입` | 가입 페이지가 없습니다. 새 계정은 Google · 카카오 로그인으로 만듭니다 |
| 언어 | 지금은 한국어만 있습니다 |
