# 시작 전 재시도와 생방송 수집 종료

2026-09-18 LEN 실전 관측에서 발견한 두 문제를 다룬다. 이번 변경은 과거 프로젝트의 파이프라인용이다.

## 시작 전

감시 스케줄러는 계속 실행되고, 각각의 짧은 브라우저 시도는 종료될 수 있다.
링크가 없으면 pending으로 돌아가고 다음 감시 주기에 공식 행사 페이지를 다시 탐색한다.
확인된 동일 행사에 시작 전 안내가 있으면 NOT_LIVE_YET으로 기록하며, 등록 상태를 저장하고
같은 경로를 다시 확인한다. 기다리는 동안 정상 경로를 실패 경로로 제외하거나 과거 행사로 이동하지 않는다.
webinar.net의 날짜 없는 대기 모달도 최신 행사 증거와 동일 행사 URL이 확인된 경우에만 인정한다.
숨겨진 안내, 일반 페이지 문구, 명시적으로 다른 날짜·종목·분기 정보는 대기 근거로 인정하지 않는다.
방송이 열리면 Enter/재생 조작, 미디어 진행 확인, 가상 오디오 검사를 거쳐 수집에 넘긴다.

이 동작은 같은 브라우저 탭을 항상 유지하는 설계가 아니다. 같은 스케줄러가 새 브라우저 시도를
이어가며 공식 행사 경로와 등록 상태를 유지하는 설계다. 사이트가 등록 상태를 쿠키에 저장하지
않으면 다음 시도에서 다시 등록이 필요할 수 있다.

## 수집 중

`WEBCAST_LIFECYCLE=live`로 실행한 오디오 수집 셸이 생방송 감독 모드를 켠다.
이때 브라우저는 기존 `WEBCAST_HOLD_SECONDS=3600` 제한으로 닫히지 않는다.
STT와 소스 감독 프로세스가 수집 종료 및 정리를 맡는다. 수동 브라우저 실행과 과거 영상의
유한 hold 시간은 기존대로 동작한다.

현재 행사임을 확인한 페이지의 보이는 명시적 종료 안내가 일정 시간 지속되고 재생 중인 미디어가
없으면 `event_ended` 신호를 기록한다. 다른 행사·숨겨진 안내, 테스트 음원의 ended 속성,
단순 무음·일시정지·네트워크 EOF만으로 행사 종료를 확정하지 않는다.
종료 신호는 call/session/run 식별자와 생성 시각을 포함하며 이전 실행의 파일은 사용할 수 없다.

실제 종료가 확인되면 PCM 생산자를 정지하고 FFmpeg가 마지막에 내보내는 음성까지 저장한다.
STT는 남은 파일·큐·마지막 짧은 윈도를 처리한 후 종료한다. 감독 프로세스는 선택된 브라우저나
미디어 fallback이 사라진 경우도 감지하여 끊긴 스트림을 정상 완료로 오인하지 않는다.
PCM 파일 전달을 끈 직접 Pulse 입력도 종료 신호 후 녹음 프로세스를 정지하고 마지막 음성을 처리한다.
녹음 프로세스가 종료 요청에 응답하지 않으면 30초 뒤 미완료로 처리한다. 이미 녹음이 끝났다면
남은 STT 처리 시간에는 이 30초 제한을 적용하지 않는다.

## 완료와 미완료

날짜 기반 콜은 충분한 텍스트, 같은 종료 행의 행사 확인·성공 자격, `event_ended` 사유가
모두 있어야 completed가 된다. DB 장애 후 로컬 보관 파일을 복구하는 경로도 같은 조건을 적용한다.
이전 워커가 남긴 bounded_capture_complete, speech_idle_timeout, input_ended 사유만으로
새로운 완료 판정을 내리지 않는다. 과거에 이미 completed로 저장된 기록은 이번 배포로 소급 변경하지 않는다.

생방송 시간/구간 한도, 무발화, 소스 단절은 미완료 종료 코드와 사유를 기록한다.
미완료 세션의 텍스트는 보존하고, 여전히 감시 시간 범위 안에 있는 콜은 약 1분 뒤 새 세션으로
재연결한다. 재연결 간의 공백까지 복구했다는 보장은 없다. 인증·접근 차단은 별도 재시도 정책을 따른다.

| 설정 | 기본값 | 의미 |
|---|---:|---|
| STT_MAX_SESSION_SECONDS | live 14400초 | 4시간 안전 한도. 도달하면 미완료이며 콜 종료 증거가 아님 |
| STT_INITIAL_SPEECH_TIMEOUT_SECONDS | 3600초 | 첫 발화 이전 대기 음악/안내를 기다리는 한도 |
| STT_NO_TEXT_TIMEOUT_SECONDS | 600초 | 발화 이후 텍스트가 없는 경우의 관측 한도. 종료 확정이 아님 |
| STT_NO_CHUNK_TIMEOUT_SECONDS | 45초 | 입력 음성 바이트가 들어오지 않을 때의 감시 한도 |
| STT_LIVE_DRAIN_TIMEOUT_SECONDS | 30초 | 종료 신호 뒤 녹음 프로세스의 정지 대기. 이미 저장된 음성의 STT 처리 시간은 제외 |
| WEBCAST_LIVE_END_CONFIRM_SECONDS | 10초 | 명시적인 현재 행사 종료 안내가 지속되어야 하는 시간 |
| WEBCAST_LIVE_END_POLL_SECONDS | 2초 | 종료 상태 확인 주기 |
| DATE_STREAM_CAPTURE_CONTINUATION_RETRY_MINUTES | 1분 | 미완료 생방송의 재연결 대기 |

기존 환경에 짧은 STT_MAX_SESSION_SECONDS를 명시했다면 그 설정이 우선한다.
4시간을 넘는 행사, 종료 안내를 제공하지 않는 플레이어, 감시 시간 범위 밖의 재연결은 별도 운영 설정이 필요하다.
종료 근거가 없으면 완료라고 단정하지 않고 미완료로 남기는 쪽을 선택한다.

## 검증 방법과 범위

`RUN_LOCAL_BROWSER_SMOKE=1 RUN_LOCAL_CAPTURE_SMOKE=1 python -m unittest discover -s data_pipeline/tests`

- `test_live_transition_chain`: 실제 Chromium·셸·FFmpeg·PulseAudio로 링크 없음 → 두 번 대기 → Enter → 음성 감지 → 수집 요청을 한 스케줄러에서 검사한다. DB는 메모리 저장소이며 최종 Whisper 실행 경계는 대체한다.
- `test_live_lifetime`: 실제 브라우저 유지, 명시적 종료, 다른 행사/재생 중 iframe 보호 및 소스 감독을 검사한다.
- `test_live_capture_lifecycle`: 실제 reader 스레드·큐·전사 루프를 가상 시계/입력/모델로 실행하여 6600초 콜, 마지막 음성 처리, 제한·단절·오래된 종료 파일을 검사한다.
- `test_pcm_handoff`: 실제 자식 프로세스가 종료 신호 후 내보내는 마지막 128KB까지 소비자에 전달하는지 검사한다.
- `test_live_completion_evidence`: 실제 SQLite SQL 집계/업데이트로 미완료·이전 세션을 거부하고 정상 종료만 완료하는지 검사한다. MySQL 행 잠금 동작은 이 테스트 범위에 포함되지 않는다.
- `tools/debug/live_completion_smoke.py`: 로컬 합성 발화와 실제 tiny 모델을 사용해 브라우저→가상 오디오→Whisper→마지막 오디오 배출→종료를 연결한다. DB 저장 함수만 로컬 테스트 파일로 대체하며 실제 서비스나 백엔드에는 전송하지 않는다.

이 검증은 새 외부 생방송을 관측한 결과가 아니다. 다음 실전에서는 시작 전 대기, 실제 발화 시작,
질의응답 마지막 부분과 사이트 종료 안내, 최종 event_ended 기록까지 함께 대조해야 한다.

실제 Whisper 연결 시험은 40.031초 재생 중 32.948초를 처리하고 4개 구간·514자를 저장했다.
종료 사유는 event_ended이며 버퍼에서 버린 바이트는 0이었다. 다만 기존 재생 준비 확인 후 PCM을
시작하는 조건 때문에 시험 음원의 첫 약 7초는 수집되지 않았다. 이번 검증은 기존 hold 한도 이후의
재생 유지와 정상 종료 후 잔여 음성 처리를 확인한 것이며, 재생 시작부터 모든 음성을 확보했다는 뜻은 아니다.
