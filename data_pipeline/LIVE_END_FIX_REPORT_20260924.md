## CTAS의 직접 실패 원인

기존 URL은 `https://edge.media-server.com/mmc/p/6agfne3p`, 실제 페이지는 끝에 `/`가 붙는 같은 이벤트 주소였다. 페이지가 History API로 주소를 정규화하여 HTTP redirect 추적으로 보완되지 않았다. `provider_event_id()`에 해당 제공사 지원이 없어 `same_event_route()`가 이를 다른 주소로 판정했다. 날짜·분기와 공식 링크의 근거는 있었으나 `LIVE_TARGET_UNCONFIRMED`로 입력폼 처리 전에 중단됐다. 이후 공식 IR 대체 경로의 CAPTCHA도 재시도 성공을 막았다.

수정은 `edge.media-server.com/mmc/p/{event_id}` 형식의 동일 이벤트 ID에서 끝 슬래시 차이만 허용한다. 다른 이벤트 ID, query 값·순서, fragment, authority는 동일한 것으로 확대하지 않는다. 입력폼 허용 정책을 추가로 해제한 변경이 아니다.

수정 후 00:26:50 실제 사이트에서 registration=passed, 00:27:11 가상 오디오 signal_present, 00:27:27 첫 텍스트 저장을 확인했다. 다만 실제 사용한 HLS 재생목록에 `#EXT-X-ENDLIST`가 있고, MEDIA-SEQUENCE=0, 966개 구간의 길이 합계가 3,879.888초(64분 39.888초)였다. 재생 위치 0초와 시작 안내부터 수집됐으므로 현재 CTAS는 재방송이다. 경로 검증용 수집으로 구분하며 생방송 수집 성공으로 계산하지 않는다. 같은 날짜·이벤트 검증은 생방송/재방송 구분과 다르다.

## 종료 처리 변경

- Q4의 실제 `Broadcast has ended, thanks for watching!` 문구와 일반 div 표시를 인식한다. 검증된 해당 이벤트 화면 안에서만 인정하고, 다른 이벤트·숨은 요소·내비게이션·기사 영역을 제외한다.
- STT에서 명확한 전체 콜 종료 안내와 disconnect 안내를 함께 찾는다. 충분한 선행 음성과 이후 처리한 음성 60초, 2회 이상 추가 발화 없는 구간, 처리 대기 15초 이하를 확인한다. 중간에 짧은 말이라도 실제 발화가 이어지면 취소한다. 단순 침묵·감사·Q&A 종료만으로는 종료하지 않는다.
- 현재 실행·종목·날짜·캡처 세션·브라우저에서 검증한 URL의 증거가 일치해야 종료 신호를 기록한다. 기존 PCM 정리, STT 잔여 입력 처리와 저장 확인을 거쳐 종료한다. 10분 무발화 자체를 성공 처리하는 방식은 유지하지 않는다.
- 사후 확인한 행사는 `ended`로 재수집에서 제외한다. 기존의 정상 수집 완료 `completed`와 구분한다. Yahoo/Nasdaq 일정 갱신도 종료 상태를 되돌리지 않는다.
- 사후 API는 증거와 원본 파일 SHA-256, 현재 일정 버전·날짜·주소·세션을 검증한다. 활성 작업/lease가 있으면 거절한다. 이미 시작한 재방송은 원본 생방송 시도와의 연결까지 확인해야 대표 세션을 복원할 수 있다.
